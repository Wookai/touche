# CLAUDE.md — touche

Free, open-source touch-typing trainer for kids and adults, FR + EN, hosted as a static site on GitHub Pages. No accounts, no analytics. **This repo is public and standalone** (ADR 0001): nothing here may name family members, hosts, keys or private repos, and nothing may depend on a private repo, package, preset or plugin. Read `DESIGN.md` before touching the engine, the UI or the content pipeline; it holds the research findings, the ten teaching principles (P1–P10) with their proxy metrics, the learner model, the generator spec and the stack rationale. Every behavioural change must be traceable to one of those principles or to a logged observation.

## Layout

```
engine/      TypeScript, zero DOM/browser deps — logger, model, generator, scheduler, simulated learner.
             src/ typechecks with no DOM or Node lib; bin/ holds the Node entry points (sim)
web/         React 18 + TypeScript + Vite; TanStack Router; Zustand; IndexedDB via idb; imports engine.
             UI strings in web/src/i18n/{fr,en}.json, hand-written
pipeline/    Python 3.15 (uv, pytest, strict baseline) — frequency lists, graded word lists, kids sentences
             (LLM, offline only), corpus chunking, log analysis. Writes data/, never runs at request time
api/         (does not exist) FastAPI + SQLite blob store; see DESIGN.md → Stack. Do not create it without an ADR
data/
  layouts/   fr-ch.json  fr-fr.json  en-us.json  en-gb.json   (physical key → chars, finger, hand, row)
  lang/      fr/  en/    words.json  kids-words.json  kids-sentences.json  corpus/*.txt   (generated)
  schema/    JSON Schema exported from the pipeline's pydantic models; TS types are generated from it
docs/        decisions/ (one short ADR per non-obvious choice)
.github/     ci.yml (the one required check; deploys web/ to Pages from main), audit.yml (weekly
             vulnerability audits), zizmor.yml
```

## Hard rules

- `engine/src` never imports from `web/`, `engine/bin` or `engine/test`, and never touches `window`, `document`, `localStorage`, timers. Biome's restricted-imports override enforces the imports, the typecheck the globals; keep `lib` and `types` empty there.
- `web/` is the only thing deployed. It must work with `api/` absent, unreachable or disabled.
- Keystroke identity is `KeyboardEvent.code` (physical key). `.key` is used only to detect layout and resolve the character. Model units are characters and bigrams of characters; never key the model on `.key`.
- Generator is deterministic given `(profileState, langData, layout, lessonType, seed)`. Property tests assert: only unlocked characters, no word repeated within a lesson, length within the mode's target for the profile's rolling WPM (2–3 min adults, ≤ 2 min kids), single language per lesson.
- Unlock is gated on accuracy (`err < 3%` over the last N occurrences: 100 adults, 200 kids) and only secondarily on latency. Never unlock on speed alone (P3).
- Kids mode: lesson ≤ 2 min, session cap 5 min, no visible speed targets, no speed bursts, finger highlight on. Kids content comes only from `kids-words.json` / `kids-sentences.json`.
- All learner data stays in the browser. `web/` makes no network request except for its own static assets. If a feature needs more, write an ADR explaining why and stop.
- `data/lang/**` is generated by `pipeline/`; commit the script change and the regenerated output in the same PR. Never hand-edit it. Every file must validate against `data/schema/`.
- Licences: record the licence of every word list and corpus in `data/LICENSES.md` before adding it. Unknown licence = don't ship it. Never copy code or data from GPL/AGPL projects (Monkeytype, keybr); ADR 0002.
- LLM calls run only on a developer machine, through one module with a cache keyed on (prompt, model). The cache and the reviewed output are committed; CI never calls a model and holds no model key (ADR 0003).
- Python: the baseline in `pipeline/pyproject.toml` (ruff ALL, basedpyright recommended, pytest strict, 80% branch coverage) is never loosened; an ignore names a full rule code with a reason. No notebooks.
- TypeScript: the baseline in `biome.jsonc` (every Biome rule at error severity, formatter, import order) is never loosened; a rule turned off or a `biome-ignore` names the rule with a reason. `engine/bin/**` is the only place Node modules may be imported.
- Frontend: no new state library, CSS framework or component kit without an ADR. Components are plain functions; styling is CSS modules; one global theme file. Lazy-load routes, keep the initial bundle small (the first lesson should load fast on a school Chromebook).

## Working style

- Read `DESIGN.md` and any ADR touching your area before starting. If a request conflicts with a principle there, say so and propose an ADR rather than silently diverging.
- Small PRs, one concern each. Engine changes come with tests; generator changes come with a simulator run (`npm run sim`) and before/after numbers in the PR description; pipeline changes come with the diff of regenerated data.
- Prefer deleting over adding. The UI is thin on purpose.
- French strings go in `web/src/i18n/fr.json`, never inline. Typographic apostrophes and guillemets in all user-facing French.
- When unsure about a pedagogical choice, default to the more conservative option (accuracy over speed, shorter over longer, fewer new keys) and note it as an open question in `DESIGN.md`.

## Commands

```
npm install                 # web + engine (workspaces); Node 24 (.nvmrc)
npm run dev                 # web dev server
npm run lint                # biome: lint, format check, import order (npm run format writes the fixes)
npm run typecheck           # tsc per project (engine/src without DOM or Node)
npm test                    # vitest: engine unit + property tests, web tests
npm run sim                 # simulated learners through the scheduler, sessions-to-target
npm run build               # production build → web/dist
npm run knip                # unused files, exports and dependencies across the workspaces

cd pipeline && uv sync --all-groups
uv run pytest --cov --cov-branch          # pipeline tests
uv run ruff format . && uv run ruff check . && uv run basedpyright
uv run touche-pipeline all    # rebuild data/lang/** (network; kids sentences come from the committed cache)
uv run touche-pipeline check  # validate data/ against data/schema/
```

## PRs and review

- Every change goes through a PR on a `<type>/<issue>-<slug>` branch; `main` requires a green `ci`. The maintainer merges.
- Content needs the maintainer's explicit review, never just green CI: anything under `data/` or `pipeline/`, word lists, kids sentences and prompts, licences, `web/src/i18n/`, `DESIGN.md`, ADRs and `.github/`. Say in the PR when it touches these.
- End every session by updating `STATUS.md` in the same PR (done, open in order, needs the maintainer, health); keep it under 100 lines.

## Gotchas

- GitHub Pages has no SPA fallback: use hash history.
- Pin every action to a commit SHA with the version in a comment; zizmor fails CI otherwise.
